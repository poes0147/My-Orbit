# My Orbit

취업·창업을 준비하는 청년이 자신의 경험과 강점을 AI와 함께 정리하고, 모바일 프로필과 직접 만든 NFC 클레이 오브제(‘나의 별’)로 소개하도록 돕는 퍼스널 브랜딩 서비스입니다. 초기에는 대학·청년지원기관 워크숍에서 사용성을 검증합니다.

## 기술 스택

Next.js App Router · React · TypeScript · Tailwind CSS · Supabase(PostgreSQL·Auth 연결, Storage 후속) · Vercel

## 개발 시작

필요 환경: Node.js LTS와 npm

```bash
npm install
npm run dev
```

개발 서버는 [http://localhost:3000](http://localhost:3000)에서 확인합니다. `.env.example`을 `.env.local`로 복사하고 Supabase Connect에서 받은 프로젝트 URL과 Publishable key를 입력합니다. 실제 값이 들어 있는 `.env.local`은 Git에 올리지 않습니다. 소셜 로그인은 Supabase OAuth와 서버 세션 쿠키를 사용합니다. 실제 AI 생성에는 서버 전용 API 키도 필요합니다.

| 명령 | 내용 |
|---|---|
| `npm run dev` | 로컬 개발 서버 실행 |
| `npm run lint` | ESLint 검사 |
| `npm run build` | Next.js 프로덕션 빌드 |
| `npm run start` | 빌드 결과 실행 |
| `node --test scripts/test-database.mjs` | 외부 DB 접속 없이 마이그레이션·RLS·저장·공개·공동 와이파이 제한 검증 |

## 현재 상태

Google·Kakao 로그인, 관리자 워크숍 코드 관리, 이력서 PDF·텍스트 분석, AI 초안 생성·편집, 비공개 프로필 저장, 공개·해제, ‘나의 별’ 클레이 가이드, NFC 최초 연결·목적지 변경이 구현되어 있습니다. 조회수 집계와 맞춤 후속 질문은 아직 구현하지 않았습니다.

초안 저장은 프로필 반영·공개와 별개입니다. 미리보기에서 **내 프로필로 저장**하면 비공개 프로필로 반영하고, 대시보드에서 다시 편집할 수 있습니다. 다른 사람이 보려면 프로필 편집 화면에서 **공개 발행하기**를 선택합니다. 공개 중인 프로필을 수정해 저장하면 공개 페이지에도 반영됩니다. 초안으로 교체하려면 먼저 공개를 해제합니다.

배포 주소는 [my-orbit-web.vercel.app](https://my-orbit-web.vercel.app)입니다. 코드 병합, 웹 배포, DB 적용 상태는 각각 확인합니다. 개발·운영은 현재 하나의 Supabase 프로젝트를 공유하므로 회귀 테스트는 별도 메모리 DB에서 수행합니다. 최신 검증 범위와 남은 실기기 확인은 [2026-11-10 보완 기록](./docs/reviews/2026-11-10-launch-hardening.md)을 참고하세요.

## 주요 경로

| 경로 | 용도 |
|---|---|
| `/login` | 참여자 로그인 진입 화면 |
| `/session` | 워크숍 참여 세션 진입 |
| `/builder` | 프로필 작성 영역 |
| `/dashboard` | 참여자 프로필·진행 현황 |
| `/settings` | 계정 설정 |
| `/p/{user_slug}` | 외부 방문자용 공개 프로필 |
| `/t/{tag_id}` | NFC·QR 고정 주소. 선택한 명함·외부 링크·공개 프로필로 이동하거나 연결 중지 안내 |
| `/dashboard/cards` | 프로필과 독립된 본인 명함 등록·편집·삭제 |
| `/t/{tag_id}/contact` | 현재 연결된 명함의 연락처 파일. 비활성·전환·삭제 후에는 제공하지 않음 |
| `/tags/bind/{tag_id}` | 로그인한 사용자가 일회용 코드로 본인 계정에 태그를 최초 등록 (공개 프로필 불필요) |
| `/admin/nfc-tags` | 관리자 전용 NFC 태그 개별 발급·목록·등록 링크 복사 (신규 마이그레이션 적용 필요) |
| `/admin/workshops` | 관리자 전용 코드 발급·전체 조회·참여 종료 |
| `/admin` | 관리자 홈·코드 관리·클레이 관리 공통 메뉴 |
| `/admin/sessions` | 관리자 화면 별칭 |

`/builder/preview`는 저장된 초안 미리보기, `/profiles/{profile_id}/edit`는 저장된 프로필 편집, `/admin/clay-materials`는 관리자 재료·배합 관리 화면입니다.

관리자 계정은 참여자 화면의 **관리자 공간**에서 전용 화면으로 이동합니다. PC에서는 사이드바, 모바일에서는 **관리 메뉴**를 사용하며 참여자 화면으로 돌아갈 수 있습니다. [관리자 화면 검증 기록](./docs/reviews/2026-11-10-admin-console.md)에 확인 범위와 남은 실제 계정 테스트를 기록합니다.

### 개발용 NFC 태그 발급

`20261111141428_admin_nfc_tags.sql` 적용 후 관리자 → **NFC 태그 관리**에서 1개씩 발급합니다. NFC 기록용 URL만 칩에 쓰고, 사용자 등록 링크와 일회용 코드는 따로 전달합니다. 코드는 결과 창에서만 확인되며 닫으면 복구할 수 없습니다. 태그 ID는 칩 제조 UID가 아닙니다. 응답 유실 시 같은 요청으로 재확인하며 새 태그를 자동 발급하지 않습니다. 코드까지 유실된 태그는 배포하지 말고 새로 발급하세요. 휴대폰 테스트에는 HTTPS 배포 주소를 사용하세요.

DB 운영자용 기존 `private.issue_nfc_tag()`는 유지합니다. 관리자 조회는 기존 태그도 포함하며 코드 해시·사용자 개인정보를 반환하지 않습니다. [관리자 NFC 검증 기록](./docs/reviews/2026-11-11-admin-nfc-tags.md)에서 적용 상태를 확인하세요.

연결한 오브제는 대시보드의 **내 NFC 오브제**에서 명함·외부 HTTPS 주소·공개 프로필·연결 중지 중 하나를 선택합니다. 기존 태그와 QR 주소는 그대로 사용합니다. 최초 등록은 로그인과 일회용 등록 코드만 필요하며, 연결 중지 상태로 시작합니다. 명함은 프로필 작성·공개 없이 사용할 수 있습니다. 명함 저장만으로는 공개되지 않으며 오브제에 연결할 때 공유할 정보를 확인합니다. 휴대폰 연락처 저장은 방문자의 최종 확인이 필요합니다.

독립 명함 기능의 DB 적용 순서와 검증 범위는 [NFC 수동 스위칭 검토 기록](docs/reviews/2026-11-11-nfc-contact-cards.md)을 참고하세요. 공유 원격 DB에 새 마이그레이션을 적용하기 전에는 새 화면을 사용할 수 없습니다.

## 개발 흐름

기능 요구사항과 인수 조건은 ign8t 프로젝트 문서와 작업 스펙을 기준으로 합니다. 구현을 시작하기 전에 기준 컨텍스트·마스터 스펙·다음 작업을 확인하고, 선택한 작업의 상세 스펙이 없으면 먼저 보완합니다. 스펙에 없는 구현을 임의로 추가하지 않습니다.

브랜치 분리와 병합은 사용자가 직접 관리합니다. Codex는 현재 작업공간에서 구현하고 변경 사항과 확인 결과를 보고합니다. 작업 내용을 `dev`에 반영할 때는 이를 설명하는 PR을 남깁니다. `main`은 상용 배포용으로 유지합니다. 현재 배포 연결 상태는 README의 “현재 상태”를 확인하세요.

개발 전에 변경할 스택에 적합한 모델을 먼저 추천하고, 사용자가 이해하기 쉽도록 현재 단계와 막힌 이유를 쉬운 말로 공유합니다.

## 제품 원칙

- 공개 프로필에는 사용자가 확인하고 공개하기로 한 정보만 표시합니다.
- 이력서 원본과 AI 대화 등 개인 자료는 비공개로 취급하고, 강사 화면에도 기본적으로 노출하지 않습니다.
- DB 접근은 서버 권한 확인과 Supabase RLS 정책을 함께 적용합니다. UI에서 버튼을 숨기는 것만으로 권한을 보호하지 않습니다.
- NFC는 태그에 미리 기록된 URL을 서버에서 프로필로 연결합니다. 브라우저에서 NFC 칩에 직접 쓰는 기능은 제품 범위에 포함하지 않습니다.
