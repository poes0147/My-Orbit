# 3단계 프로필 입력 폼 구현 준비

작성일: 2026-11-02

상태: 사용자 직접 구현 요청에 따라 수동 입력 UI 구현 및 브라우저 확인 완료. 상세 ign8t task spec은 미생성 상태이며, DB·인증·AI 연동과 최종 인수 조건 대조는 남아 있음.

## 기준과 현재 상태

ign8t My Orbit 마스터 스펙 및 다음 작업 조회 결과를 기준으로 정리했다. 이 문서는 구현 준비 기록이며 승인된 기능 스펙을 대신하지 않는다.

선택할 작업: **3단계 위저드 입력 폼 UI (1단계: 경험 키워드, 2단계: 성과/역할, 3단계: 가치관 및 톤)**.

2026-11-02 조회 시 작업은 `todo`이며, 생성된 task spec은 없다. 기존 앱셸 작업의 `/builder`는 세 단계 이름을 보여주는 정적 안내 화면이고 입력·이동·검증 기능은 없다. 해당 코드는 현재 `origin/feature/auth-session`에서 확인했으며 현재 체크아웃된 문서 브랜치에는 포함되지 않았다. 브랜치 통합은 사용자가 관리한다.

## 마스터 스펙에 확정된 요구사항

2026-11-02 사용자 확인: 현재는 사용자가 직접 작성하는 3단계 폼을 진행한다. 이력서 업로드·AI 분석 후 입력 항목 자동 채우기는 추후 기능으로 분리했다. ign8t의 「이력서 AI 분석 기반 프로필 입력 자동 채우기」 기능 요청으로 저장했으며 검토 대기 중이다.

- 모바일 우선 `/builder` 작업 영역에서 세 단계로 입력한다.
- 1단계는 주요 프로젝트, 활동 분야 및 경험 키워드를 선택하거나 입력한다.
- 2단계는 프로젝트의 역할, 성과 및 해결한 과제를 STAR 구조로 입력한다.
- 3단계는 지향 가치관과 원하는 소개 톤을 선택한다.
- 이후 AI 프로필 초안과 오브제 가이드 생성 작업으로 연결된다.
- 사용자 원본 입력과 AI 생성 문안, 최종 공개 문안을 구분한다.
- 개인 입력 자료는 비공개로 취급한다.

## ign8t 상세 스펙에 필요한 항목

1. 각 입력 필드의 이름, 필수 여부, 글자 수 제한과 선택지.
2. 경험이나 프로젝트를 여러 개 입력할 수 있는지 및 최대 개수.
3. 이전·다음 단계 이동과 입력값 유지, 오류 표시 방식.
4. 새로고침·이탈·재접속 시 임시 저장 범위, 저장 위치와 삭제 기준.
5. 인증·워크숍 세션이 없는 경우의 진입 및 안내 방식.
6. 마지막 단계 제출 동작과 AI 생성 작업에 전달할 데이터 형식.
7. Supabase·AI 연동 전 UI 작업의 범위와 완료 기준.
8. 모바일 키보드, 포커스 이동 및 화면 읽기 도구를 고려한 접근성 조건.

## 스펙 준비 후 구현 순서

1. 앱셸이 포함된 현재 작업공간을 확인하고 설치된 Next.js의 관련 문서를 읽는다.
2. 승인된 필드 정의와 단계별 입력 상태를 구성한다.
3. 단계 이동·검증·진행 표시를 연결한다.
4. 스펙에 정해진 임시 저장과 제출 경계를 구현한다.
5. 실제 입력 및 오류 흐름을 인수 조건과 대조하고 확인 결과를 기록한다.
6. 미완성 연동을 명시하고, 전체 인수 조건이 충족되면 ign8t 검토 단계로 옮긴다.

AI 생성, DB 저장 및 인증이 연결되지 않은 경우에는 해당 기능까지 완료했다고 보고하지 않는다.

## 구현 기록 (2026-11-02)

- `/builder`에서 경험·키워드, STAR 구조의 역할·성과, 가치·소개 톤을 순서대로 입력한다.
- 경험명 120자, 키워드 200자, STAR 항목별 500자를 UI 입력 상한으로 적용했다. 가치는 제시된 여섯 항목에서 1~3개, 톤은 세 항목에서 하나를 고른다. 이 선택지와 상한은 이번 UI 구현의 기본값이며 ign8t 상세 스펙 확정 시 재대조한다.
- 빈 값과 공백 입력을 검증하고, 오류와 단계 이동 시 포커스를 안내한다.
- 뒤로 이동하거나 검토 화면에서 수정해도 입력값을 유지한다. 새로고침과 화면 이탈 이후에는 유지하지 않는다. 영구 저장은 아직 구현하지 않았으며 이를 화면에 안내한다.
- 마지막 단계는 입력 내용 검토 화면으로 이동한다. 서버 저장·AI 생성 요청은 전송하지 않는다.
- 구현 파일: `src/components/builder/profile-wizard.tsx`, `src/app/(workspace)/builder/page.tsx`.
- ESLint, TypeScript 검사 통과. `next build --webpack` 통과. 기본 Turbopack 빌드는 CSS 처리 프로세스 실행 오류로 실패했다.
- Playwright로 390px 화면에서 필수값 오류, 단계 이동 입력값 유지, 선택 개수 제한, 검토·수정 흐름과 가로 넘침 없음 확인.
- 브랜치 생성·전환·커밋·푸시는 수행하지 않았다. 현재 문서 브랜치 작업공간에 변경 파일로 남겨 사용자가 분리·통합한다.

### CSS 미적용 수정

사용자 화면에서 Tailwind 스타일 미적용이 확인됐다. 기존 Tailwind 처리는 Turbopack 전용 규칙이었으며, Webpack 검증 빌드에서는 유틸리티 스타일이 생성되지 않았다. `@tailwindcss/postcss` 의존성과 `postcss.config.mjs`를 복구하고 전용 Turbopack 규칙을 제거했다. Webpack 재빌드 통과 후 모바일 스크린샷으로 입력란·단계 표시·버튼 모양을 확인했다. 계산된 스타일에서 최대 폭 576px, 모바일 여백 32px/20px, 버튼 배경 적용 및 가로 넘침 없음을 확인했다. 최초 동작 검사에는 실제 스타일 검증이 빠졌으므로, 이후 화면 확인에는 계산된 스타일과 스크린샷을 함께 확인한다.

### 대시보드 공통 앱셸 적용

독립 화면으로 만든 빌더를 기존 `(workspace)/layout.tsx` 기반으로 수정했다. 기존 앱셸·대시보드 및 메뉴 목적지의 소스를 `origin/feature/auth-session`에서 현재 작업공간으로 가져왔으며 브랜치는 전환하거나 병합하지 않았다. 빌더의 별도 서비스 로고·화면 폭·외부 여백을 제거하고 대시보드와 같은 헤더·하단 메뉴·본문 여백을 사용한다. 390px 브라우저에서 대시보드 → 만들기 메뉴 이동, 두 화면의 동일 본문 폭과 여백, 검증 메시지 표시 및 가로 넘침 없음을 확인했다. Webpack 빌드와 린트 통과.
