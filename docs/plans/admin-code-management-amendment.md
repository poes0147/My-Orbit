# 관리자 코드 발급·총괄 관리 스펙 수정안

상태: ign8t PRD·TRD 원문 수정·저장·승인 완료. 최신 마스터 스펙에도 관리자 발급·전체 관리·PC 반응형 기준이 반영됐음을 MCP 재조회로 확인했다. 사용자 승인 후 56 Sparks로 기존 작업 상세 스펙을 재생성했고 `is_stale=false`와 관리자 전용 인수 조건을 확인했다.
대상: My Orbit, 기존 작업 `0bb8c87b-3c77-4be9-aebd-450325b43f71`.

## 확정된 수정 요구사항

- 참여 코드 발급 주체는 관리자다. 강사는 참여 코드를 발급하지 않는다.
- 관리자는 관리자 페이지에서 전체 참여 코드를 총괄 관리한다.
- 관리자와 강사는 구분된 권한이어야 하며 화면뿐 아니라 서버와 DB에서 검사한다.
- 기존 코드 고유성, 안전한 난수 생성, 유효 기간, 종료 후 참여 차단 및 참여 등록 검증은 유지한다.

## ign8t 문서 수정 대상

- 마스터 스펙 ‘여정 4’의 강사 코드 발급을 관리자 코드 발급·총괄 관리로 정정한다.
- 대상 사용자와 권한에 관리자를 명시하고 강사와 구분한다.
- 기존 작업 제목·범위·사용자 흐름·API 권한·RLS·인수 조건에서 발급 주체를 관리자로 정정한다.
- 기존 강사의 본인 코드 관리 화면을 관리자의 전체 코드 관리 화면으로 변경한다.
- 관리자만 발급·전체 조회·관리할 수 있고 강사와 참여자는 이를 수행할 수 없다는 인수 조건을 추가한다.
- 코드 발급자의 `created_by`와 강사 역할을 동일시하지 않는다. 현재 강사 본인 소유 기준 정책은 관리자 총괄 관리 요구에 맞춰 재설계한다.

## 상세 스펙에서 명시할 항목

- 관리자 계정 지정 절차 및 최초 관리자 계정.
- 코드 ‘관리’의 구체 범위: 종료·재개, 만료 시간 변경, 재발급, 검색/필터 등 각 동작의 포함 여부.
- 강사가 담당 워크숍 코드를 볼 수 있는지, 관리자가 강사를 배정하는 기능이 이번 범위에 포함되는지.
- 기존 참여자의 작업 접근과 신규 참여 허용 여부를 종료 상태에서 어떻게 처리할지.

위 미확정 항목은 사용자 요구사항으로 단정하거나 제품 코드에 임의 반영하지 않는다.

## 반응형 화면 제안

- 관리자 총괄 관리는 PC의 넓은 화면에서 코드 목록과 관리 기능을 사용하도록 설계한다. 모바일에서도 기본 작업을 지원한다.
- 참여자 공통 앱셸의 고정 모바일 폭을 검토하고 PC 가로 배치를 별도 정의한다.
- 관리자 화면 추가와 참여자 공통 앱셸 변경의 구현 범위·인수 조건을 스펙에서 구분한다.

## 현재 구현과 차이

문서 수정 당시에는 강사 발급 기준 코드가 남아 있어 작업을 진행 중으로 돌렸다. 이후 스택 재점검 요청으로 관리자 전용 API/RLS·PC 표·모바일 카드를 구현하고 실제 DB·브라우저 검증을 마쳤다. 현재 구현과 적용된 개발 DB는 관리자 발급 기준이다. [재점검 기록](../reviews/2026-11-03-stack-audit.md)을 따른다.

## 재생성 결과 검토

- AC-1 관리자 생성, AC-2 강사·참여자 생성 차단, AC-3 코드 규격/고유성, AC-4 기존 참여 연동, AC-5 종료 후 입장 차단, AC-6 PC 표/모바일 조작을 명시한다.
- 백로그 제목의 ‘강사’ 표현은 그대로 남았지만 상세 스펙 Intent/Non-Goals/Risks에서 최신 상위 요구사항에 따라 발급 주체를 관리자로 강제한다고 명시한다.
- 생성된 예시 모델에는 `code`, 기본 정원30, nullable 만료 등 실제 DB와 다른 예시가 있다. 구현 시 실제 `session_code`, 기본 정원35, NOT NULL 만료 및 기존 상태 제약/외래키를 우선 재사용한다. 코드 예시 때문에 동작 중인 스키마를 임의 변형하지 않는다.
- 새 상세 스펙에 맞춰 충돌 재시도 상한을 5회로 보정하고 성공·소진·권한 오류 분기를 검증했다.
