# 강점 분석 v0.1 구현·검증

ign8t: `7e647ef8-a12a-4bfe-a3ae-323f518e7a08` / spec `afebe222-dcdc-47a2-bf50-168472b45826`.

## 사용자 흐름
- 이력서 분석에서 사용자가 적용한 경험 또는 직접 쓴 경험으로 강점 분석을 실행한다.
- 24개 고정 강점 사전에서 AI가 문맥과 행동 인용을 추출한다. 프로그램이 원문 일치, 주체/실행 여부, 중복 경험·행동을 확인한 뒤 최대 3개를 정렬한다.
- 검토 패널에서 근거를 보고 제외하거나 직접 작성한 태그를 추가한다. 강점이 적으면 보완 질문을 표시하며 채워 넣지 않는다.
- 질문 입력 중 선택은 브라우저 임시 초안에 보관하고 프로필 생성 시 계정 초안에 함께 저장한다. 저장된 초안 편집에서는 확인한 태그가 기존 자동 저장을 통해 계정에 저장된다.
- 실제 프로필 반영은 기존 미리보기의 '내 프로필로 저장'으로만 수행한다. 이미 공개된 프로필을 초안으로 덮어쓰지 않는다.
- 입력 변경 시 이전 분석 적용을 막고 새 분석을 안내한다. 저장된 편집기의 최신 태그를 전체 재생성에도 전달한다.

## 스펙 조정 및 경계
- 실제 입력 계약은 `answers.step_responses.project`이며 가상의 `step_responses` 컬럼을 만들지 않았다.
- 기존 이력서 원본은 저장하지 않는다. 사용자가 검토해 폼에 적용한 내용만 분석한다. 입력 API는 최대 4개 경험을 지원하지만 기존 위저드 UI는 대표 경험 하나를 사용한다.
- 분석 결과/인용만 24시간 캐시한다. 만료 즉시 조회 차단, 5분 간격 삭제 예약. 전체 원문을 추가 저장하지 않는다. 공개 프로필에는 태그 문자열만 반영한다.
- 캐시 키는 입력·모델·사전·프롬프트·규칙 버전을 포함하고 사용자별로 분리한다.
- 분석 실패에 가짜 강점 폴백을 하지 않는다. 기존 초안/프로필은 유지한다.
- 기존 DB 공개 조건(이름·소개·최소 1개 태그)은 유지한다. 비공개 초안/프로필 저장은 0–3개를 허용한다.
- 단순 기간 제한, 초과 근무, 관찰 뒤 개선 조치 등을 강점 인정의 필수조건으로 넣지 않았다.
- 보완 질문은 경험명과 추가 행동 설명을 요청하는 안전한 템플릿이다. 별도 유료 질문 생성 호출이나 적응형 면담 엔진은 이번 범위가 아니다.
- 순위는 같은 추출 결과에 대해 결정적이다. AI의 문맥 판단은 v0.1 휴리스틱으로, 심리측정이나 정확한 개인 능력 판정이 아니다.
- 색상 연결 없음. 기존 모델과 의존성 유지.

## 검증 근거
- `node --import ./scripts/fixtures/resolve-ts.mjs --test scripts/test-strengths.mjs scripts/test-strengths-api.mjs scripts/test-strengths-db.mjs`: 13개 통과.
- 기존 CI의 단위/DB 묶음: 19개 통과, 기존 실서버용 익명 프로젝트 API 검사 1개는 환경 조건으로 SKIP. 별도 builder draft/rate-limit/workshop/resume PDF 검사는 모두 통과.
- ESLint 전체 검사, TypeScript 검사 통과. 최종 webpack production build 통과.
- 실제 OpenAI 호출 1회: 가상 카페·클레이 경험 입력 → 분석력/설명력/관찰력 각 1개 근거 반환. 사용자의 실제 이력서나 계정 자료는 보내지 않음.
- 실제 React 컴포넌트를 사용한 격리 UI 서버: 320px/1280px에서 가로 넘침 없음. 근거 펼침, 선택 반영, 변경된 입력의 적용 차단 확인.
- 저장된 초안 편집기 → 강점 1개 적용 → 자동 PATCH → 재생성 요청에 동일 태그 유지 확인. 새로고침 후 1개 복원, 모두 해제 후 0개 자동 저장 확인. 이 브라우저 검사에서 인증/HTTP 저장은 fixture였고, 실제 SQL 저장·RLS는 별도 PGlite 검사로 검증했다.
- 독립 리뷰의 두 발견(긍정 행동의 부정문 오판, 재생성 시 편집기 선택 손실)을 수정하고 회귀 확인했다.

## 미확인/배포 전 항목
- 운영 Supabase 마이그레이션 적용, Vercel 배포, 실제 로그인 계정으로 전체 HTTP→DB→공개 화면 연결은 아직 수행하지 않았다. 기존 운영 데이터는 수정하지 않았다.
- `supabase db advisors --type security --fail-on error`는 로컬 Supabase/Docker 스택이 없어 127.0.0.1:54322 연결 실패. SQL 권한 테스트는 PGlite에서 통과했지만 Supabase advisors 성공으로 대체 표기하지 않는다.
- 실제 사용자 데이터셋 평가, 다국어/복합 문장·의미적 사건 중복 정확도 평가는 후속 개선 대상이다.
- 커밋/푸시/PR/병합은 수행하지 않았다. 다음 단계는 dev PR 검토 후 DB 마이그레이션 및 배포 검증이다.
